# 펴부기 (Pyeobugi)

웹캠으로 거북목(머리 내밀기)과 고개 숙임처럼 목에 부담을 주는 자세를 감지해 바른 자세를 돕는 데스크톱 앱 (macOS / Windows).
두 자세는 구분하지 않고 하나의 "나쁜 자세"로 판정합니다 ([ADR 0002](docs/adr/0002-single-bad-posture-class.md)).

- **온디바이스 감지**: 영상, 얼굴, 자세 수치는 기기 밖으로 나가지 않고, 서버에는 익명 이벤트 로그만 전송
- **저전력**: 경량 얼굴 검출 모델 + 상태에 따라 감지 주기를 조절해 발열과 배터리 소모 최소화
- **데모 모드**: 얼굴 박스와 키포인트, 각도·점수·감지 시점 그래프를 화면에 표시 (시연·녹화용)

## 어떻게 동작하나

1. **얼굴 검출**: MediaPipe Face Detector(BlazeFace short-range, 0.23MB)를 앱에 내장해 CPU에서 실행합니다.
   카메라는 320x240으로 열고, 한 번 추론에 약 10ms가 걸립니다.
2. **각도 근사**: 얼굴 키포인트 6개로 고개 각도(pitch)를 근사하고, 처음에 잡은 개인 기준값과 비교해 점수를 냅니다.
3. **판정**: 시간 기준 EMA로 신호를 안정화하고, 3초 이상 유지돼야 나쁜 자세로 판정하고(회복은 2초), 진입과 회복 기준을 다르게 둬서 깜빡임을 막습니다.
4. **적응형 감지 주기**: 평소 1Hz, 자세가 바뀌는 중일 때만 4Hz, 1분 넘게 자리를 비우면 0.33Hz로 돌립니다.
   고정 7.5Hz였던 프로토타입보다 추론 횟수가 약 6배 적습니다.

자세한 근거는 [ADR 0001](docs/adr/0001-face-detector-for-low-power-detection.md)에 있습니다.

## 정확도 (v0.1.0, 1인·60초 × 6개 라벨 기록)

> 아래 수치는 3개 표본 평균 스무딩을 쓰던 v0.1.0 기준입니다. 시간 기준 EMA로 바꾼 뒤에는 아직 다시 측정하지 않았습니다.

| 자세 | 나쁜 자세로 판정된 비율 | 평균 추론 |
| --- | --- | --- |
| 바른 자세 | 4.2% | 1.23Hz |
| 거북목(머리 내밀기) | 77.5% | 1.18Hz |
| 고개 숙임 | 95.0% | 1.17Hz |

- 바른 자세 오탐은 같은 거리에서 0%이고, 기준을 다시 잡지 않고 10~20cm 뒤로 앉은 기록에서만 발생했습니다.
- 거북목과 고개 숙임이 100%가 아닌 건 3초 판정 대기와 당시의 3개 표본 평균 처리 때문입니다.
- 데이터가 적어서 아직 상수는 조정하지 않았습니다. 기록 방법은 아래 [정확도 평가용 기록](#정확도-평가용-기록)을 참고하세요.

## 알려진 한계

- 앉는 거리가 바뀌면 각도 기준이 약 5° 이동합니다.
- 전력 소모는 직접 측정하지 않았습니다(추론 횟수와 시간으로만 비교).
- 패키징된 앱에서는 모델 로딩을 확인하지 않았습니다. 지금은 `npm run dev` 기준입니다.
- 필기처럼 정상적인 짧은 숙임도 3초가 넘으면 알림이 갑니다.

## 정확도 평가용 기록

영상은 저장하지 않고, 얼굴 키포인트 좌표와 각도·크기만 `userData/recordings/`에 JSON으로 저장합니다.

1. `npm run dev` → 바르게 앉아 **기준 잡기** → **데모 모드** 체크
2. 라벨과 시간을 고르고 **기록 시작** (기록 중에는 5Hz로 고정 샘플링)
   - **바른 자세**: 평소처럼 화면을 보며 타이핑·읽기
   - **거북목(머리 내밀기)**: 등은 그대로 두고 머리만 화면 쪽으로 내밀기
   - **고개 숙임**: 책상 위 휴대폰이나 노트 보기
   - **필기·자료 보기**: 평소처럼 노트에 적거나 종이 자료를 보다가 다시 화면 보기를 자연스럽게 반복
     (알림 없이 넘어가야 하는 짧은 숙임이 몇 초인지 재서, 고개 숙임 판정 대기 시간을 정하는 데 씀)
3. 같은 라벨을 조명·거리를 바꿔 2~3번씩 반복하면 좋습니다
4. 분석

```bash
npm run analyze              # 기본 기록 폴더 전체
npm run analyze -- <파일|폴더>
```

라벨별 각도 잡음, 바른 자세 대비 분리도(Cohen's d, 최적 임계값), 실제 엔진을 적응형 주기로 재생한 오탐·검출률,
숙임 구간 길이 분포(중앙값·p90·최대)를 표로 출력합니다.

## 개선된 기준 잡기와 평가

`기준 잡기`를 누르면 약 5초 동안 정면을 보며 바르게 앉아 주세요. 수집 중에는 2Hz로 감지하고,
움직임이 크거나 얼굴 미검출이 3번 이상이면 저장하지 않고 다시 시도하도록 안내합니다. 실패해도 기존 기준값은 유지됩니다.
현재 안정성 기준은 초기 설정이므로 실제 사용자 기록으로 검증해야 합니다.

분석은 기록별로 저장된 기준값을 사용합니다. 기준이 없는 이전 기록은 **기준 없는 바른 자세 기록의 평균**을
사용하므로, 같은 사람·환경의 파일끼리 분석하세요. 필요한 기준 기록이 없으면 분석을 중단합니다.
원본 키포인트가 있는 기록은 현재 기하 검사를 다시 적용하고, 없는 기록은 저장된 각도·크기를 사용합니다.

추가 출력은 오탐 횟수·시간, 판정 불가 표본/시간 비율, 감지·복구 지연과 미감지/미복구 구간 수입니다.
판정 불가는 얼굴 미검출과 기하 검사 탈락을 포함합니다. 지연은 소급한 이벤트 시각이 아닌 **실제 판정 시각**으로
계산하며, `–`는 측정 불가입니다. 감지 비율과 지연은 기록의 마지막 관측 시각까지 재생한 근사값입니다.
기준이 없는 데이터에서 찾은 최적 임계값과 정확도는 같은 데이터에 대한 탐색 결과이며 별도 검증 성능이 아닙니다.

기존 기록은 전체 구간의 라벨이 일정하다고 가정합니다. 실제 자세 전환과 복구 지연을 평가하려면 로컬 JSON에
아래 선택 필드를 추가하세요. 시각은 기록 시작 기준 밀리초, 구간은 시작 포함·끝 제외이며 정렬되고 겹치지 않아야 합니다.
`GOOD`/`BAD`는 모델 점수가 아닌 실제 관찰로 표시합니다. 필기 기록은 이 표시가 없으면 오탐·지연을 계산하지 않습니다.

```json
"groundTruth": [
  { "fromMs": 0, "toMs": 10000, "posture": "GOOD" },
  { "fromMs": 10000, "toMs": 20000, "posture": "BAD" },
  { "fromMs": 20000, "toMs": 30000, "posture": "GOOD" }
]
```

복구 지연은 BAD→GOOD 전환 직전 엔진이 나쁜 자세 상태인 경우만 측정합니다. 얼굴 소실에 따른 초기화는
복구로 세지 않습니다. 오탐 횟수는 GOOD 구간에서 발생한 나쁜 자세 진입 횟수이고, 오탐 시간은 GOOD 구간과
나쁜 자세 표시 시간의 교집합입니다. 따라서 회복이 늦으면 새 오탐 진입 없이도 오탐 시간이 생길 수 있습니다.

## 로컬 피드백 상태와 거리 변화 안내

감지 신호는 표본 수 대신 경과 시간을 반영하는 EMA(시간 상수 1초)로 처리합니다.
자세 화면은 판정 대기·회복 대기·판정 불가 상태를 구분하며, 데모 모드에는 상태와 지속 시간을 표시합니다.
얼굴 크기가 기준 대비 25% 이상 달라진 상태가 8초 유지되면 기준 재설정을 안내합니다.
기준은 자동 변경하지 않으며, 실제 거리와 머리 내밀기를 구별하는 기능은 아닙니다.

비네트/복구 보상 연결에 필요한 로컬 상태와 종료 사유는
[프론트 연동 문서](docs/frontend-feedback.md)를 참고하세요. 얼굴 소실이나 재설정은 실제 회복과 구분됩니다.
