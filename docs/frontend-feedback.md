# 로컬 자세 피드백 연결

`useDetection()`의 `view.feedback`는 비네트와 복구 보상에 사용할 로컬 상태입니다.
렌더러에서만 사용하며 서버 이벤트의 종류나 payload는 변경하지 않습니다.
별도 Electron 오버레이 창을 사용할 경우 이 상태를 전달할 로컬 IPC는 프론트 통합 시 추가해야 합니다.
이번 구현은 상태 제공과 재설정 안내까지이며, 화면 전체 비네트나 소리 렌더링은 포함하지 않습니다.

## 상태

| `phase` | 의미 | 권장 화면 처리 |
| --- | --- | --- |
| `UNCALIBRATED` | 개인 기준 없음 | 기준 잡기 안내 |
| `UNAVAILABLE` | 엔진이 얼굴을 놓침(3초 이상 미검출) | 비네트·보상 중단 |
| `GOOD` | 정자세 | 비네트 없음 |
| `PENDING_BAD` | 나쁜 자세 진입 대기 | 아직 비네트 시작하지 않음 |
| `BAD` | 지속 조건을 만족한 나쁜 자세 | 점수·지속 시간으로 강도 계산 |
| `RECOVERING` | 회복 유지 조건을 확인 중 | 비네트를 부드럽게 줄이고 확정 회복을 기다림 |

- `score`: 현재 필터링한 점수. 판정 불가/미설정이면 `null`.
- `severity`: 확정 나쁜 자세 상태의 현재 점수 단계. `MILD`, `MODERATE`, `SEVERE` 또는 `null`.
- `badSince`: 확정된 나쁜 자세의 시작 시각. 진입 대기 시작으로 소급한 로컬 epoch 밀리초.
- `badDurationMs`: 그 시작부터 현재 표본까지의 경과 시간. 진입 대기 시간도 포함합니다.
  판정 불가일 때는 0입니다. 3초 미만의 잠깐 미검출은 같은 에피소드로 보고 경과 시간을 계속 표시합니다.
- `lastExit`: 가장 최근 종료 이벤트. `{ id, reason, occurredAt, detectedAt }` 또는 `null`.
  `occurredAt`은 소급한 종료 시각이고 `detectedAt`은 실제 판정 시각입니다.

## 복구 보상

`lastExit.reason`은 다음 세 가지입니다.

- `RECOVERED`: 실제 정자세가 회복 유지 조건을 만족함.
- `FACE_LOST`: 얼굴 소실/유효하지 않은 표본이 지속돼 판정 종료.
- `RECALIBRATED`: 기준 재설정으로 기존 판정 종료.

보상은 `RECOVERED`에서만 검토하고 나머지 이유에는 지급하지 않습니다.
`lastExit`는 이후 표본에서도 유지되므로 프론트는 `id`를 한 번만 소비해야 합니다.
같은 `useDetection` 인스턴스에서 절전 복귀 후에도 ID는 증가하지만, 앱 재실행/훅 재마운트 시에는 초기화됩니다.
뷰가 새로 마운트될 때 이미 존재하는 종료 이벤트는 소비된 것으로 처리하고, 이후 새 ID만 처리하세요.
지연 표시를 피하려면 현재 상태가 `GOOD`이고 `detectedAt`이 최근인 경우만 애니메이션을 시작하세요.

각도/얼굴 크기/점수나 이 상태 객체를 `POST /api/events`에 넣지 않습니다.
기존 사용 시간 집계는 모든 종료 사유에서 구간을 닫고, 보상 여부만 종료 사유에 따라 달라집니다.

## 거리 변화 안내

`view.distance.suggested`가 참이면 자세 화면에 기준 재설정 안내를 표시합니다.
초기 조건은 얼굴 높이 비율이 기준에서 25% 이상 변한 상태가 같은 방향으로 8초 유지되는 것입니다.
안내 이후 15% 미만으로 돌아오면 해제합니다. 얼굴 미검출, 표본 간격 1.6초 초과, 캘리브레이션 중에는
누적을 초기화합니다. 기준값은 사용자가 재설정을 완료한 경우에만 바뀝니다.

얼굴 크기는 거리의 대용 신호이므로 실제 거리 변화와 머리 내밀기를 확실히 구별하지 못합니다.
따라서 자동 보정이나 자세 면제에 사용하지 않고, 바르게 앉은 뒤 재설정하도록 안내만 합니다.
25%/15%/8초 값은 사용자 데이터로 검증할 초기 설정입니다.
